# WP00 · NAS 接入探路

独立 Python 3.12 脚本，不导入项目模块，不挂载操作系统网络盘，不建立后端或前端。需要人在公司内网实际运行；真实 SMB 和 ACL 需现场验收。

## 准备与依赖

Windows PowerShell（安装 Python 3.12 后）：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r scripts/probe/requirements.txt
```

macOS / Linux：

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r scripts/probe/requirements.txt
```

运行依赖为 `smbprotocol==1.16.1`，其中包含 `smbclient`。显式传入用户名、密码并使用 NTLM，不使用操作系统登录身份。每个账号单独传入 `connection_cache`，避免服务器名相同导致复用一条 TCP 连接。

由 NAS 管理员提前准备**专用测试共享文件夹**及两个目录，例如：

| 对象 | A：普通测试账号 | B：终审测试账号 |
|---|---|---|
| `探路/读写测试` | 可列、读、创建、追加、改名、删除 | 同左 |
| `探路/权限对照` | 可列、读；禁止创建和写入 | 可列、读、创建、写入、删除 |

目录名称、权限由现场设置，不是业务目录约定。需要测试其他 ACL 组合时，可调整权限并重复运行，再逐项人工核对结果；例如把读写测试目录设成 A 只读，会产生预期的失败和后续跳过，退出码也会非零。

两个目录须已存在；`--test-dir`、`--read-only-dir` 都是相对于 `--share` 的路径，不能带 `\\NAS\共享`、`/volume1`、盘符或 `..`。不要选正式资产目录或放有业务资料的目录，不要使用系统账号。NAS 应启用 SMB2/3 并支持签名，工作机须能访问 TCP 445。禁用测试共享文件夹的来宾访问，授予两个测试账号所需的 SMB 权限。

## 运行

推荐不提供 `--password`，脚本按 A、B 顺序隐藏输入密码，避免密码进入命令历史和进程参数。终端无法隐藏输入时会退出，不退回明文回显。

```powershell
.\.venv\Scripts\python.exe scripts/probe/probe_nas.py `
  --host 192.168.0.177 `
  --share "探路" --test-dir "读写测试" --read-only-dir "权限对照" `
  --user "测试上传人" --user "测试终审"
```

macOS / Linux：

```sh
.venv/bin/python scripts/probe/probe_nas.py \
  --host 192.168.0.177 \
  --share '探路' --test-dir '读写测试' --read-only-dir '权限对照' \
  --user '测试上传人' --user '测试终审'
```

也支持按出现顺序配对两组 `--user` / `--password`，例如 `--user A --password '占位密码A' --user B --password '占位密码B'`。这是必需的兼容参数，真实密码写进命令行可能被 shell 历史或进程查看器记录，推荐隐藏输入；不要把真实命令写进报告。密码以 `-` 开头时用 `--password=值`。密码参数应全部提供或全部省略。

参数说明：

| 参数 | 含义 |
|---|---|
| `--host` | IPv4 或主机名；不带协议、端口、路径；不支持 IPv6 字面量 |
| `--share` | 一个共享文件夹名，不能是路径 |
| `--test-dir` | 已存在的读写测试目录，相对于共享文件夹 |
| `--read-only-dir` | 已存在的权限对照目录，A 只读、B 读写；必填，不自动推断业务目录 |
| `--user` / `--password` | 最多两组；首个为 A、第二个为 B；只传一组可做单账号探路，但双账号项会跳过 |
| `--timeout` | 默认 30 秒，限制 SMB 建连，后续文件操作使用 SMB 库自己的超时 |

脚本使用 NTLM 建立要求签名的 SMB 会话，拒绝来宾和匿名登录。身份认证成功后，后续目录和文件操作复用该账号会话，并记录各项实际权限。

## 每项结果的含义

| 测试 | 通过说明 / 核对方式 |
|---|---|
| SMB 身份认证 | 测试账号建立独立的 SMB 会话，后续逐项核对共享目录的读写权限 |
| 列目录 | 当前账号能访问指定读写测试目录；只输出目录项数量，不打印已有文件名 |
| 新建文件夹 | 创建随机 `wp00-A/B-<UUID>` 子目录，原有目录不会被覆盖或复用 |
| 追加写入 20MiB | 20 × 1MiB，总计 20,971,520 字节；每块关闭后重新 `ab` 打开，覆盖多次追加语义 |
| 读回 SHA-256 | 以 1MiB 块读取，长度与写入内容的 SHA-256 均一致 |
| 同卷 rename | 在同一父目录、同一共享文件夹内仅调用服务端 rename；计时只含这次调用，必须 **<1 秒**；不执行复制降级 |
| rename 后校验 | 确认文件内容仍可读取且摘要、长度一致；rename 超过 1 秒也会记录为失败并按实际新路径清理 |
| 删除/清理 | 反向删除本次记录的文件、目录；不递归扫描删除，不改用另一个账号清理 |
| 中文路径 | `中文目录/验证文件.txt` 读写及摘要一致 |
| 带空格路径 | `05 详情页/验证文件.txt` 读写及摘要一致 |
| 200 字符长路径 | 200 个 ASCII 字符的末级目录，加父目录及中文文件名；共享内相对路径超过 200 字符，输出实际字符数；不把 200 个汉字放进一个目录名，以免混入 NAS 单名称字节上限问题 |
| A 只读目录拒写 | 先确认目录可列，再尝试创建唯一文件；仅明确的权限拒绝算通过，记录异常类型及 NTSTATUS / errno 原文；不存在、断网、共享冲突都算失败 |
| B 同目录写权限对照 | B 在与 A 相同目录内创建、写入并删除文件成功，验证两条连接的权限不同 |
| 双账号同时存活 | 保留 A 连接期间建立 B；确认缓存与 TCP 连接对象不同，再用原会话按 A→B→A 列目录，无需交错线程写入 |
| B 加入后 A 仍拒写 | 再次确认 A 未误用 B 凭据；应仍明确拒绝写入 |
| 关闭 SMB | 全部测试后释放会话；失败也会尝试关闭并显示结果 |

每步即时显示成功/失败/跳过、耗时及详情，结束输出 Markdown 汇总表。异常原文保留，但已知密码及其 URL 编码形式会隐藏，认证协议调试日志保持关闭。若含真实主机或目录信息，按公司内网资料保存。

退出码：`0` 全部执行项通过；`1` 有失败或跳过（包含单账号未完成双账号验证）；`2` 参数错误；`130` 用户中断。预期的 A 权限拒绝计为成功；意外允许写入计为失败，并仍用 A 尝试删除测试文件。

脚本不自动覆盖 `RESULT.md`，该文件是留给人工填写的验收模板。将本次终端汇总粘入模板，补充 NAS 后台的实际 ACL、版本、日期与结论；失败不能留空或改写成成功。如果清理失败、强制终止或网络断开，请按输出中的 UUID 残留路径由相应账号/管理员人工确认后清理，不可删除整个测试父目录。不要把含密码的命令行或调试抓包写进报告。

## 哪些结果意味着设计需要调整

- SMB 身份认证失败：检查 TCP 445、SMB2/3、NTLM 和签名策略，以及账号状态。已认证但目录访问失败时，检查共享和目录 ACL。
- 单账号成功、双账号失败或 A 加入 B 后获得写权限：会话隔离未验证，不能进入依赖该机制的正式开发；需核对缓存、凭据传递及 NAS 配置。
- ACL 与测试不符：先核查共享权限、继承权限、群组和拒绝项。正式目录必须由 NAS 拦截普通员工写入，不能使用系统账号补写。
- 内容长度/摘要不一致：追加或读取链路不可用，需排查 SMB 语义后再设计分片上传。
- rename ≥1 秒：不能认可“瞬时移动”；重复测量并核查 NAS 负载、共享配置。**本测试只验证同一父目录 rename，不证明未来临时区→正式目录的跨目录 ACL 和同卷条件**，现场还须确认两者在同一共享文件夹、同一卷，不存在挂载/跨卷映射；跨共享文件夹不由本脚本测试。
- 中文、空格、长路径失败：记录实际路径长度、错误类型和 NAS 配置，后续预检与路径限制需依据实测调整。
- 无法删除或关闭会话：检查 ACL、连接回收及错误恢复方案，并清理残留。

## 本地自动化测试

```powershell
.\.venv\Scripts\python.exe -m pip install -r scripts/probe/requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest scripts/probe/tests -q
.\.venv\Scripts\python.exe scripts/probe/probe_nas.py --help
```

macOS / Linux 将解释器替换为 `.venv/bin/python`。测试使用本地临时目录与模拟 SMB，不读取真实凭据，不访问外部服务；真实 NAS 仅由人运行探路脚本，不纳入默认 pytest。不创建工程配置或前端，因此无前端构建步骤。

实现依据：[smbprotocol 官方仓库](https://github.com/jborean93/smbprotocol)、[独立 connection_cache 参数实现](https://github.com/jborean93/smbprotocol/blob/v1.16.1/src/smbclient/_pool.py)。
