# V1.1.7 专项交付报告

基准为 V1.1.5 提交 `7e211d9c720dcbe60e09304318a6989c56268e62`。此次交付包含 SMB 登录、跨环境恢复、管理员界面、检索和备份保护。

## 根因

- V1.1.5 生产登录通过 DSM API 查询认证接口、验证密码并注销，再以同一凭据创建 SMB 会话。DSM 管理端口、证书和认证 API 因而成为登录前置条件。
- NAS 存放正式文件、三层档案和发布凭据。项目与商品目录、标签、关系、短链接和向量依靠本地 SQLite。新检出的环境新建 SQLite 后，实时 NAS 浏览仍能读取经授权的文件，但已入库视图和两种搜索缺少正式目录记录。原有恢复流程主要通过离线脚本执行。

## 登录与权限

生产登录依次协商 SMB、以本人账号认证、验证会话和连接业务共享，最后检查本地工作台角色并创建登录令牌。本人 SMB 文件会话由设备对应的工作台会话 ID 管理。退出或断线回收当前设备会话，后续需要本人重新登录。开发模式使用模拟账号和 LocalFs。

SMB 签名、拒绝 Guest 和匿名、禁止跨共享 DFS、按实际操作执行 NAS 权限等约束由连接或文件接口执行。NAS 的错误按网络、协议协商、身份验证、账号限制和共享连接阶段处理。服务器无法提供确切原因时显示通用错误。工作台禁用状态单独判断。浏览器登录链路继续沿用原有传输方式、Cookie 和跨站防护。

运行时读取 V1.1.5 的旧 DSM 键时将其忽略。NAS 地址、共享、工作根、账号、密钥和 AI 配置继续由原配置管理。Mac 可直接用回环监听连接真实 NAS，Windows 启动、自检和部署以 SMB TCP 445 为准。

## 恢复机制

| 阶段 | 结果 |
| --- | --- |
| 启动抽查 | 限量读取正式档案与短发布凭据，标明本地已登记、可能缺失、首次部署待确认、系统账号不足或 NAS 暂不可访问。损坏的 SQLite 或缺少原密钥会触发离线恢复提示。 |
| 有效备份 | 核验清单、文件 SHA-256、SQLite 完整性与外键、原密钥及资产身份。暂存库执行迁移，保留角色、审核、日志和向量，废止原会话。目标配置保留新环境的服务参数。 |
| 差异计划 | 对比每个稳定项目身份、已发布版本、原档案指纹与本地记录，报告一致、缺失、可补齐、较老本地版本、冲突或暂不可确认。 |
| 档案恢复 | 经管理员确认后，在只读 NAS 会话中复核发布凭据及文件 SHA-256。每个项目的必要向量通过校验后，按事务写入 SQLite，保留原标识，更新号段上限。 |
| 派生数据 | 快速匹配使用恢复后的本地字段。已有合格向量按模型、代次、维度与文本哈希复用；缺失向量用原确认文本重算。授权后可按需生成预览，也可批量补齐缩略图。 |

正式资产恢复沿用原三层档案和发布凭据格式。空库、损坏备份、原密钥丢失、档案冲突、缺少权限各有独立结果。缺少发布证据的旧档案进入人工核验。仅凭档案可重建的内容以实际归档字段为准，完整角色、审核记录、操作日志和未归档资料优先从备份恢复。

生产备份要求本地已存在正式记录，且资产状态获得确认或具备既有有效备份的连续性。未确认及发现差异的环境、空库和只读实例受到备份限制。可启用入库和入库后操作的合并延迟备份。

## 升级与恢复操作

1. 在目标机器设置正确的 NAS 共享与业务区域，配置受控管理员与负责读取正式区和备份区的系统账号。并行核验使用 `recovery.read_only: true`，数据目录使用本机磁盘。
2. 管理员登录后，从「管理 → 资产恢复与索引管理」检测状态和备份候选。先核验最近合适的备份，在独立目录验证配置、用户、链接和数据。新环境提供空库提示和操作入口。
3. 若备份较早，查看暂存库的 NAS 差异计划。没有可用备份时扫描正式档案。确认要执行的计划，查看成功、待确认和失败报告。正式索引和缩略图可在同一页面补齐。
4. 整库切换在维护窗口完成。停止旧部署的写入，保留完整原数据目录、配置和密钥，切换到验证过的目标库。新域名需要能解析原短链接标识。使用授权账号通过真实读取权限核对项目、搜索、预览及下载，然后启用业务写入。
5. 在生产启用定时备份前，复查档案差异。现场发现在目标实例已经发生新写入时，先停写并核对变更再决定如何回滚。

命令行、停机切换、Windows ACL 与回滚见 [仓库启动和恢复说明](../README.md) 及 [Windows 部署手册](../deploy/README.md#数据恢复)。

## 验收环境与边界

本地验收使用各自独立的 SQLite 和同一套隔离的模拟 NAS。用工作台完成上传、AI 打标、人工确认、初审和终审，随后验证受控备份恢复与无备份档案恢复。快速匹配检查零模型调用。语义检索使用可重复的假模型输入，通过正式向量候选、排序与读取权限链路。恢复对比使用档案投影、数据库记录和实际文件指纹。

| 核验对象 | A 原环境 | B 备份恢复 | C 档案重建 |
| --- | ---: | ---: | ---: |
| 项目 | 1 | 1 | 1 |
| 商品 | 2 | 2 | 2 |
| 文件 | 3 | 3 | 3 |
| 人工确认标签 | 22 | 22 | 22 |
| 套装关系 | 1 | 1 | 1 |
| 永久链接 | 6 | 6 | 6 |
| 正式向量 | 2 条，32 维 | 原向量一致 | 假模型重算结果一致 |

B 和 C 的正式档案投影 SHA-256 均与 A 相同。三个环境均验证两种搜索、预览、下载 SHA-256、永久链接和未授权账号的读取限制。B 还验证了旧登录令牌失效，并对比迁移前后的资产身份清单。A 和 B 均停止后，C 作为唯一写入实例正常发布 P002。新对象 ID 大于恢复时的编号上限，原档案与向量保持一致。针对性异常演练覆盖 SQLite 迁移失败、解密密钥不匹配、NAS 断开、待审批次占用、档案缺证据、向量失败、原子提交中断和重复执行。

本地全量后端 461 项、前端 125 项通过，TypeScript 检查及 Vite 生产构建通过。默认配置排除 15 项依赖真实 NAS 或真实百炼的测试。构建仍报告一个主 JavaScript 分块超过 500 kB。

现场还需使用真实群晖账号验证 TCP 445、签名、共享权限、单设备退出和多设备隔离，使用经授权的百炼模型验证向量生成与搜索，以及在 Windows 主机演练安装、升级、停机切换与回滚。只有具备有效归档证据和恢复账号读取权限的项目可通过档案恢复。旧实例与隔离实例的正式 NAS 写入需按部署手册交接。
