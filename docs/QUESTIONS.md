### WP08 审核超期的工作日口径

入库流程 §11、§16 以工作日计算超期，未提供公司节假日与调休表。目前按北京时间、周一到周五计算，从进入本级审核的时刻起算，超过配置期限才出现管理员待办。若要按公司排班提醒，需要另行提供日历。

### WP09 正式目录归属、档案与向量接续

- 入库流程 §14.1 的档案表仍举展示名作文件名。采用同文档 §12 的商品编号，JSON 结束标记存在对象内。项目 TXT 额外保存可解析的结构化恢复段。
- 执行器按附件的最新要求接入实际 Embedding。初期用 SQLite BLOB 保存可验证的 float32 向量，保留模型版本与索引代次。向量索引加载、查询和正式代次切换关联 WP11。
- 同卷 rename 前，为已验证的待入库目录写入短期的随机归属标记。若文件已离开临时区，但正式目标无法通过标记或持久检查点及清单验证，保持入库异常并等待核对。
- 从 NAS 档案恢复的卡片柜先登记为 `ingesting`，重新生成和核验向量后可发布。档案保留原审核身份和关系确认身份的记录。完整审核台账、用户角色与操作日志仍取决于数据库备份。

### WP10 下载和异常定位口径

- 服务器支持单个 HTTP Range，多段请求返回 416。预览及下载在当前设备的 NAS 会话中核验权限，实际发送前以同一文件句柄重读完整 SHA-256。大文件或频繁续传会增加 NAS 读量。批量界面统计服务器已发送和失败数量，文件保存情况由浏览器下载列表显示。
- 按登记位置读取时即核验 SHA-256。路径缺失时，文件名、大小和修改时间用于排序，唯一身份仍由完整指纹确认。已属于其他资产的路径不作为候选，重复副本或无法检查的目录保持待核对。物理路径校正保留业务分类和原档案。
- 历史删除状态沿用已持久化的文件、项目和历史版本记录。在没有可公开的删除时间或说明时，状态页只显示已物理删除以及返回项目列表入口。

### WP11 向量检索与查询口径

- WP09 已存四键区分的向量 BLOB，本包直接使用。sqlite-vec 加载成功时用 SQLite 的余弦函数计算，加载失败时用 NumPy。两者共用已验证的向量数据。大规模性能仍按实际库和内网延迟现场测量。
- 关键词先按字段命中筛选，结果不足时再放宽到确认值和描述。向量分数低于 0.45 的候选不进入召回，融合使用倒数排名。阈值应根据人工真实题库验证，因此先保留保守默认值。
- 同一百炼兼容接口下蓝绿代次独立。接口地址改变会使原模型身份失配，需要按已核验的模型配置恢复。供应商模型别名若会随发布改变，应使用可分别调用的明确模型 ID。首批正式向量由原 WP09 门禁建立。
- 查询结果列表只探测登记位置的 NAS 主图读取权限，已移动文件可通过 WP10 原链接定位修正后重新检索。索引任务重算文本向量时只使用正式 SQLite 文本，不读取 NAS 原件。

### WP12 · 正式位置与历史版本

- 工作台按 SQLite 当前版本指针确定公开位置。隔离预备及原物理目录会占用额外 NAS 空间。NAS 文件浏览器仍可能显示旧物理目录，工作台按当前版本与生命周期提供访问。正式部署时验收目录 ACL、NAS 容量与保留旧物理目录对日常浏览的影响。WP13 巡检需明确识别这些目录。
- 旧候选 `0010_postops` 与正式 `0018_search → 0019_postops` 为不同迁移链。若候选库投入过使用，须先做独立迁移演练，核对旧链接与历史身份后再决定数据接入方式。
- 重建 SQLite 时，若只剩 NAS 档案，需由 WP14 确定哪个目录为最后已发布版本，并同时恢复可证明的作废生效与预期删除记录。

### WP13 · 巡检处理和调度

- 入库流程 §14.2、技术架构 §14.2 和阶段提示中的「终审一键修复」与 50 项确认规则 #07 冲突。修复按钮创建项目级草稿，按同一双审流程冻结及批准，执行会话归本轮终审。
- 采用中国标准时间（Asia/Shanghai，UTC+08:00）。保留同一个调度分钟内的重启去重，错过整次调度可由管理员手动补跑。Windows 服务时区及单实例部署在 WP14 核验。
- 预期删除中的已登记路径与仍未发布的影子目录不作为丢失或未登记项。损坏档案、目录重名或指纹出现多个候选时，只报告本次证据，不能据此推断企业分类。

### WP14 · 发布环境与档案恢复证据

- 发布要求提到 Node 20，但已锁定的 Vitest 5.1.0 在 Node 20 上不受支持。构建沿用仓库的 Node 22.12+ 基线和锁文件。Windows 目标主机只安装 Python 和 NSSM。
- 旧版档案可能尚无发布凭据。正式 SQLite 提交成功后、终审设备写入凭据前也存在短暂中断窗口。恢复时禁止按时间、目录名或低一版本猜测，必须取得独立证据后显式确认。完整数据库备份优先。
- 纯档案只能恢复原项目登记的公司、行业和其他可证明的元数据。完整企业行业字典与别名、实际授权和审核日志须从 DB 备份恢复或由业务和 IT 重新核实录入。
- 规则 #02 尚有差异。当前设备即使 SMB 在线，工作台令牌过期也会停止新的分片请求，重新登录后才可续传。WP14 保留设备会话隔离和当前测试，列为正式上线前应处理的规则偏差。

### V1.1.1 · NAS 连接与工作目录
