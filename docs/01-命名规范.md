# 设计资产目录与命名规范（v1.0 · 50项规则对齐版）

> 版本：v1.0 · 2026-11-17 · 保留业务确认的目录层级与资料夹名称，按50项最终决策修订。详细审核与后续变更见 `docs/02-入库流程.md`。

## 0. 这份规范管什么

本规范规定设计资产进入 NAS 正式库时每一层文件夹叫什么名字、项目内有哪些文件夹。v0.2 按两轮业务对齐会议的结论修订。

- 工作台**只解析 `套装/` `单品/` 里的主图**，并保证从主图能回溯到所属项目和项目下的各类资料夹。资料夹里放什么、怎么放，工作台不检查、不干涉。
- 本规范分两类条款：**拦截项**是系统无法处理的，预检不让上传；**建议项**是为了库里整齐好找，预检最多提醒，由人审把关。
- 行业、企业分类由设计 BU 与产品 BU 线下商定，工作台不在上传时做任何分类检查。
- 历史项目由业务人员拉到本机、按本规范整理后，和新项目一样上传；旧库在迁移期间不动。
- 尚未确认的业务约束仅保留为建议项，不得覆盖已经确认的50项规则。

## 1. 通用字符规则（所有层级适用）

**拦截项**（系统无法处理）

| 规则 | 内容 |
| --- | --- |
| 文件系统非法字符 | 任何层级不得含 `\ / : * ? " < > \|` |
| 路径长度 | 完整路径（含文件名）≤ 200 字符，防 Windows 260 字符上限 |
| 系统保留名 | 业务上传的包里不得出现 `套装档案` `单品档案` `_历史版本` `_项目档案.txt` |

**建议项**（预检提醒或不检查）

| 规则 | 内容 |
| --- | --- |
| 推荐字符 | 中文、英文字母、数字、`-`、`_`；`_` 只用作项目文件夹名的分段符 |
| 不推荐 | 中点 `·`、破折号 `—`、全角标点、文件夹名以 `.pdf` 等扩展名结尾 |
| 序号写法 | 两位数字开头；序号后是否加空格【待定】（现有 `05 详情页` 有空格，`01定稿文件` 没有） |
| 长度 | 单个文件夹名 ≤ 40 字符 |
| 系统垃圾文件 | `Thumbs.db` `.DS_Store` `desktop.ini` `~$` 开头的文件：工作台自动忽略，不上传、不报错 |

## 2. 目录层级总览

正式库共四层文件夹到项目，项目内再一层。业务人员只负责「项目」及其内部，上面三层由系统按对照表创建。

```
/设计资产/
├── 01已中标项目/                          ← 第一层：中标状态（系统建）
│   └── 01酒业/                            ← 第二层：行业（系统按对照表建）
│       └── 07泸州老窖/                     ← 第三层：企业（系统按对照表建）
│           └── P2026-0012_泸州老窖_中秋礼盒/  ← 第四层：项目（业务人员建）
│               ├── 01定稿文件/
│               ├── 02设计方案/
│               ├── 03拍摄照片及视频/
│               ├── 04授权文件/
│               ├── 05 详情页/
│               ├── 套装/                   ← 全家福主图（打标）
│               ├── 单品/                   ← 全部单品主图（打标）
│               ├── 套装档案/               ← 系统生成
│               ├── 单品档案/               ← 系统生成
│               ├── _历史版本/              ← 系统生成
│               └── _项目档案.txt           ← 系统生成
├── 02未中标项目/                          ← 结构与 01 完全相同
└── _已作废项目/                           ← 整项目作废后移到这里
```

与现有目录的对应关系：现在的 `02 深度定制(归档后)` 相当于新库「行业」层的上一级，新库在它和行业之间插入了「中标状态」。项目内的五个资料夹沿用业务现有名称和顺序，只新增 `套装/` `单品/`。

## 3. 第一层：中标状态

只有两个固定文件夹，由系统创建，任何人不得新增或改名。

| 文件夹名 | 含义 |
| --- | --- |
| `01已中标项目` | 上传时勾选「已中标」的项目 |
| `02未中标项目` | 上传时勾选「未中标」的项目 |

比稿阶段的项目不入库；只有结果已定（中标或未中标）的项目才上传。【待定】是否需要第三个状态，例如「内部自研 / 无招标」。

## 4. 第二层：行业

格式：`两位序号 + 行业名`，如 `01酒业`。

- 行业怎么分、叫什么名，由设计 BU 与产品 BU **线下商定**；定了之后由管理员录入「企业→行业对照表」，系统按表创建文件夹。
- 上传时**不检查、不约束**行业归属。企业不在对照表里的，存放位置标为「待定」，由终审在通过前从现有目录树选择；目录树里没有的，等管理员录入后再通过。
- 序号从 `01` 开始，新行业追加到末尾，已有序号不重排。
- 不建「新行业」这类占位文件夹。

【待定】行业、企业层要不要保留序号。保留的好处是资源管理器里顺序固定，代价是序号不能重排。

## 5. 第三层：企业

格式：`两位序号 + 企业标准名`，如 `01茅台`、`07泸州老窖`。序号在行业内独立编。

| 规则 | 内容 |
| --- | --- |
| 企业标准名 | 对照表里每家企业只有一个标准名，其他叫法（`贵州茅台` `MOUTAI`）作为别名，用于从项目文件夹名里识别企业 |
| 长度 | 2～10 个字，用品牌简称 |
| 子品牌 | **不单独成层**（业务已确认）。茅台王子酒、1935、小茅写进项目名或商品名，必要时做成标签 |
| 企业级公共资料 | 现有的 `00茅台素材资料` 这类第一阶段不入库（业务已确认） |

企业归属同样线下商定、管理员录入，上传时不检查。

## 6. 第四层：项目文件夹

格式：**`立项编号_企业名_项目名`**，如 `P2026-0012_泸州老窖_中秋礼盒`（业务已确认）。这是业务人员自己命名的最高一层。三段用半角下划线分隔，缺段或编号段为空则拦截。

### 6.1 立项编号

| 规则 | 内容 |
| --- | --- |
| 来源 | **沿用公司立项时的唯一立项编号**（业务已确认）。格式样例【待定】，拿到后补充格式校验 |
| 历史项目 | 有公司编号的沿用；没有的由上传人**必选历史项目实际所属年份**，由系统分年度原子发放 `H{项目年份}-{四位流水}`，如 `H2023-0001`。不得默认使用上传年份；该编号是系统唯一身份，不冒充公司立项编号 |
| 唯一性 | 全库唯一，一个编号只对应一个项目；同一编号同一时间最多存在一个未完成首次入库批次（包括入库异常）；成功入库后相同编号上传转补充流程。数据库事务保证并发唯一性。 |
| 不可改 | 入库后永不变更；改名、移动、补充都沿用原编号 |

### 6.2 企业名

建议与对照表里的标准名或别名一致，系统靠它推荐存放位置。对不上的不拦截、不提醒，只是位置标「待定」由终审选。

### 6.3 项目名（建议项）

| 规则 | 内容 | 示例 |
| --- | --- | --- |
| 长度 | 2～20 个字 |  |
| 写什么 | 系列或主题 + 核心商品 | `文旅酒甄香韵锡罐`、`王子酒雨伞` |
| 不重复企业名 | 企业名已在前一段 | 不写 `茅台文旅…`，写 `文旅…` |
| 不写流程词 | `定稿` `转曲` `文件` `项目` `打印` `入库` | `汉酱酒背包定稿转曲` → `汉酱酒背包` |
| 不写数量与口号 |  | `王子酒摆台餐具30套致青春奋斗` → `王子酒摆台餐具` |
| 子品牌写在前 |  | `1935蓝牙耳机`、`小茅拍拍灯` |

一个立项编号一个文件夹，项目内不再嵌套子项目。

## 7. 项目内子文件夹

项目内的标准结构是业务现有的五个资料夹，加上新增的 `套装/` `单品/`（业务已确认）。名称按现状原样使用。

| 文件夹名 | 放什么 | 谁建 | 工作台是否解析 |
| --- | --- | --- | --- |
| `01定稿文件` | 大货源文件 | 业务人员 | 否 |
| `02设计方案` | 提案、效果图、草图 | 业务人员 | 否 |
| `03拍摄照片及视频` | 实物拍摄 | 业务人员 | 否 |
| `04授权文件` | 各类授权书 | 业务人员 | 否 |
| `05 详情页` | 电商详情页、渲染图 | 业务人员 | 否 |
| `套装` | 每个套装一张全家福主图 | 业务人员 | **是** |
| `单品` | 全部单品主图，含从套装拆出的和独立的 | 业务人员 | **是** |
| `套装档案` `单品档案` `_历史版本` `_项目档案.txt` | 系统档案 | 系统 | — |

规则：

- 五个资料夹**正式入库后必须齐全**：缺失时预检黄色提醒但不拦截，终审后系统使用终审 NAS 身份在正式入库前补齐空目录，动作幂等并记录日志。不能修改已有目录内部结构。
- **资料夹内部放什么、怎么命名，工作台不检查、不干涉**。订单明细等文件放哪个夹由业务自定【待定】。
- 根目录散文件、多出来的文件夹：不检查。
- `套装/` `单品/` 里只能是图片，不能有子文件夹或其他文件，否则拦截。**首次入库两者均无至少一张主图时必须拦截**；已入库项目只补充普通资料文件时可没有新主图。
- 上传的包里不得出现系统档案四项，出现即拦截。正式商品档案 JSON 必须以 `{product_code}.json` 命名（分别位于 `单品档案/` 或 `套装档案/`），商品名称仅存档案内部，改名不更改档案文件名。

## 8. 商品主图与套装关系

主图是搜索的对象：**一个商品一张代表性主图**，原有资料保留在资料夹里（业务已确认）。

```
套装/
├── 中秋礼盒A.jpg        ← 全家福
└── 中秋礼盒B.jpg
单品/
├── 酒瓶.jpg             ← 从 A 拆出来的
├── 月饼盒.jpg
├── 手提袋.jpg
├── 酒瓶-小.jpg          ← 从 B 拆出来的
└── 定制酒杯.jpg         ← 不属于任何套装
```

### 8.1 两个文件夹的分工

- `套装/` 只放全家福，每个套装一张。
- `单品/` 平铺放**全部**单品主图：从套装里拆出来的和独立的都在这里，不分子文件夹。
- 文件夹结构**不表达**哪个单品属于哪个套装。

### 8.2 套装与单品的关系怎么来

系统先解析全部单品，再解析每张全家福并把该项目全部单品的名称和标签交给模型，由模型**推荐**这张全家福包含哪些单品；上传人在核对页逐条**确认或修改**，如确无关联单品则显式确认「无关联单品」，与尚未核对区分。关系保留在数据库和套装／单品／项目档案中，一个单品可以属于多个套装。全家福中未提供独立主图的物件不能被自动拆分成单品。单品作废保留历史关系并暂时失效，恢复时仅自动恢复仍有效且未被后续正式修改的关系；套装作废绝不级联作废单品。

### 8.3 文件名

**由产品部门在放入文件夹时命名，具体格式【待定】**（业务已确认责任方）。对系统而言文件名只是展示名，不承担任何结构含义；商品身份靠系统发放的商品编号。以下是给产品部门的建议稿：

| 建议 | 示例 |
| --- | --- |
| 写商品本身的名字，不写企业名、项目名、编号 | `锡罐` 而不是 `茅台文旅酒甄香韵锡罐` |
| 同品多款用 `-` 接款式，每款算一个商品 | `锡罐-红` `锡罐-金` |
| 同一商品不用 `1` `2` 区分角度，多角度图放资料夹 |  |
| 同一项目内不重名 |  |
| 2～20 个字，小写扩展名 |  |

### 8.4 图片要求

| 要求 | 约束力 | 说明 |
| --- | --- | --- |
| 格式 | 拦截 | `.jpg` `.jpeg` `.png`；其他格式【待定】 |
| 一图一品 | 建议 | 单品主图里只有这一个商品；AI 识别出多个商品时标黄 |
| 清晰度 | 建议 | 允许截图，最好用清晰图（业务已确认）；不设分辨率门槛 |
| 内容 | 建议 | 正面或最能代表它的角度；尺寸标注、价格、文案会干扰打标 |

## 9. 资料夹内的文件

资料文件不打标、不搜索，只跟着项目入库和下载。工作台只卡文件系统非法字符和路径长度，其他一律不检查。

| 建议 | 说明 |
| --- | --- |
| `内容_版本或日期` | 如 `外箱展开图_终稿.ai`、`提案_20260315.pdf` |
| `01定稿文件` 只放终稿 | 过程稿放 `02设计方案` |
| 少用压缩包 | 压缩包里的文件无法被单独链接 |

## 10. 历史项目整理对照示例

历史项目由业务人员拉到本机、按本规范整理后上传。用现有 `00酒业 / 01 茅台` 下的真实文件夹名演示整理后的样子。编号为示意：有公司立项编号的用公司编号，没有的由系统发 `H` 编号。

| 现有文件夹名 | 整理后 | 改了什么 |
| --- | --- | --- |
| `01茅台文旅酒甄香韵·锡罐项目` | `H2025-0001_茅台_文旅酒甄香韵锡罐` | 加编号；企业名移到分段；去 `·`；去「项目」 |
| `03汉酱酒背包定稿转曲` | `H2025-0003_茅台_汉酱酒背包` | 去「定稿转曲」 |
| `07茅台王子酒定稿转曲-雨伞` | `H2025-0007_茅台_王子酒雨伞` | 去流程词 |
| `10茅台1935茶杯—外箱.pdf` | `H2025-0010_茅台_1935茶杯外箱` | 去 `—`；去文件夹名里的 `.pdf` |
| `21茅台王子酒摆台餐具30套致青春奋斗` | `H2025-0021_茅台_王子酒摆台餐具` | 去数量和口号 |
| `22茅台定制茅台定制中国民俗茶具套装定稿文件` | `H2025-0022_茅台_中国民俗茶具套装` | 去重复的企业名和流程词 |
| `00茅台素材资料` | （第一阶段不入库） | 企业级公共资料 |

项目内部（以 `01茅台文旅酒甄香韵·锡罐项目` 为例）：

| 现有 | 整理后 |
| --- | --- |
| `01定稿文件` `02设计方案` `03拍摄照片及视频` `04授权文件` `05 详情页` | 不变 |
| `06 …` | 保留还是并入其他夹，业务自定【待定】 |
| 根目录 `下单明细.xlsx` | 放哪个资料夹业务自定，工作台不检查 |
| 根目录 `…锡罐1.jpg` `…锡罐2.jpg` | 人工判断：两个款式则 `单品/锡罐-A.jpg` `单品/锡罐-B.jpg`；同一商品两个角度则选一张做主图 |
| `Thumbs.db` | 工作台自动忽略 |

## 11. 预检规则对照表

原则：**只拦截会让系统无法处理的问题**，整理是否规范交给人审。拦截 = 不让上传；提醒 = 标黄放行，上传人勾「已知晓」后继续，审核可见；忽略 = 自动跳过。

| # | 检查项 | 处理 |
| --- | --- | --- |
| 1 | 项目文件夹名不是 `编号_企业_项目名` 三段，或编号段为空 | 拦截 |
| 2 | 立项编号已有正式项目 | 转补充流程；同一编号已有未结束首次入库批次时禁止再次创建 |
| 3 | 任意层级含文件系统非法字符 | 拦截 |
| 4 | 路径总长超过 200 字符 | 拦截 |
| 5 | 出现系统保留的文件夹或文件 | 拦截 |
| 6 | `套装/` 或 `单品/` 里有非图片文件或子文件夹 | 拦截 |
| 7 | 首次入库 `套装/` 和 `单品/` 都没有主图 | 拦截；只有已经正式入库的项目允许文件类补充无主图 |
| 8 | 01～05 任一资料夹缺失 | 黄色提醒、允许上传；正式入库前由系统补齐空目录 |
| 9 | 项目名含中点、全角标点、空格等不推荐字符 | 提醒 |
| 10 | 根目录散文件、规定之外的文件夹、资料夹内部内容 | 不检查 |
| 11 | 主图分辨率、文件名写法、同名 | 不检查（命名规则出来后再评估） |
| 12 | `Thumbs.db` `.DS_Store` `desktop.ini` `~$` 临时文件 | 忽略 |
| 13 | 空文件夹 | 照常上传（业务要求保留空目录） |


## 12. 新版执行与稳定身份补充（50项规则）

- 每一张单品或套装代表性主图对应唯一商品编号；更换图片文件名、商品展示名和移动位置均不能更换该商品编号。主图替换由上传人选择明确的原商品 ID，不凭文件路径猜测为新增商品。
- 替换单品／套装主图时，受影响关系由上传人逐项复核，原关系在新版本完成审核与必要向量生成前保持可用；11个标签须与新AI识别结果逐项对照确认。
- 系统为项目、商品、文件及各历史文件版本保存稳定 ID 和永久链接映射；永久 URL 统一取配置项 `public_base_url` 所指定的固定内网域名。
- 项目名称或企业标准名称经两级审核更正时，路径、所属公司目录、数据库和 NAS 档案同步变更；编号及永久链接不变，必须检查目标目录冲突。
- 商品档案的 `{product_code}.json` 保留完整合法 JSON 与结束标记，项目档案记录足以在 SQLite 与全部备份丢失后重建对象及历史链接的身份和版本映射。
- 所有文件无论大小均计算完整 SHA-256；同内容不同文件保留各自独立的 file_id。未经工作台直接改写或移动属于违规，按照技术架构中巡检与告警规则处理。
- 已作废资产不出现在正常搜索，但保留原永久链接；NAS 有读取权限的用户可查看和下载尚未物理删除的历史版本。物理删除只针对作废满30天的对象，并必须通过初审、终审。

> 已有项目内五个业务资料夹的名称与内容组织方式不作额外规定，工作台不检索这些业务资料的文件正文。
