- # NAS 设计资产工作台 · 入库流程详细设计（v3.1）

  > 版本：v3.1 · 2026-11-15（v3.1：标签字段改为 11 个自由文本字段，见 9.5） 依据：两轮业务对齐会议结果（《第二轮业务确认结果与技术方案调整报告》）及其后的技术确认。 范围：从登录工作台到项目正式入库，以及入库后的补充、改名、修改标签、作废、移动、物理删除。 不含：查找与下载的详细方案、技术选型、AI 提示词细节。 相对 v2 的变更见第 17 节。 标记：**【待定】** = 尚无业务或你本人的明确结论，汇总在第 18 节。

  ------

  ## 1. 原则

  1. 工作台只做三件事：上传（入库）、查找、下载。上线后是设计资产进出 NAS 的唯一合规入口。
  2. 入库顺序：**业务整理在前，AI 打标在中，上传人核对，初审、终审两级把关，终审通过才进正式目录。**
  3. **身份和权限以 NAS 为准。** 工作台不另建账号，不设可写的服务账号。
  4. **正式目录只有终审能写。** 任何落到正式目录的变动，都由终审点击后、以终审本人的 NAS 身份执行。
  5. 工作台对项目包内部**放什么、怎么放不做干涉**。它只解析 `套装/` `单品/` 里的主图，并保证从主图能回溯到所属项目和项目下的各类资料夹。
  6. 行业、企业分类由设计 BU 与产品 BU 线下商定，上传时不做检查和约束。
  7. 不往设计文件里写任何内容。文件身份靠指纹，商品身份靠系统发放的商品编号。
  8. 外部模型只收到主图的缩小图和必要的文字，不收到 NAS 路径、账号和资料夹里的任何文件。
  9. 绕过工作台直接改动 NAS 属于违规。工作台只负责记录合规操作、发现不合规变动。

  ## 2. 账号、角色与权限

  ### 2.1 登录

  - 用户在内网浏览器打开工作台，输入自己的 NAS 账号和密码。
  - 工作台把账号密码交给 NAS 验证，通过即建立会话。
  - 密码只保存在会话内存里，用于以本人身份读写 NAS；不写入磁盘、数据库或日志。
  - 会话有效期 8 小时（可配置）。超时后需重新登录，但正在进行的上传不受影响。
  - 同一账号允许多台电脑登录，日志记录来源电脑。
  - 第一版只部署在公司内网。

  ### 2.2 角色

  工作台维护一张「NAS 账号 → 角色」表，由管理员填写。未登记的账号默认是上传人。

  | 角色   | 人数                  | 在工作台能做什么                                             |
  | ------ | --------------------- | ------------------------------------------------------------ |
  | 上传人 | 所有能登录的 NAS 用户 | 上传、核对标签、提交、处理驳回、撤回自己的批次；对已入库项目发起补充、改名、修改标签、作废；查找、下载 |
  | 初审   | 指定的若干人          | 上传人的全部能力，加上：初审                                 |
  | 终审   | 指定的若干人          | 上传人的全部能力，加上：终审、修改存放位置、通过后执行入库、发起移动、整项目作废、物理删除、执行档案修复 |
  | 管理员 | 项目负责人            | 维护角色表、标签字段、企业→行业对照表；查看巡检报告、日志、临时区占用；清理临时区；重试失败批次；更换批次责任人 |

  规则：

  - 一个人可以有多个角色。
  - **初审和终审可以上传并审核自己的批次。**
  - **同一个批次的初审人和终审人不能是同一个人。** 这是唯一的回避约束。
  - 不按行业或部门划分数据范围。
  - 审核人不在时批次积压等待，不设代理。

  ### 2.3 NAS 权限矩阵

  | 区域                  | 上传人、初审 | 终审                     | 巡检账号 |
  | --------------------- | ------------ | ------------------------ | -------- |
  | 临时区                | 读、写       | 读、写                   | 读       |
  | 正式目录 `/设计资产/` | **只读**     | 读、写、移动、改名、删除 | 读       |

  - 没有可写的服务账号。
  - **【待定】巡检账号**：巡检在凌晨运行，需要一个只读账号来列目录，密码加密保存在工作台电脑上。

  ### 2.4 每个动作用谁的身份

  | 动作                                     | 身份                       |
  | ---------------------------------------- | -------------------------- |
  | 上传、核对阶段追加主图、撤回批次         | 上传人本人                 |
  | 初审                                     | 不写 NAS                   |
  | 终审通过后的移动、发商品编号、写档案     | 终审本人                   |
  | 入库后的改名、合并、作废、移动、物理删除 | 终审本人                   |
  | 档案修复                                 | 终审本人（登录后一键执行） |
  | 清理临时区                               | 管理员本人                 |
  | 巡检                                     | 只读巡检账号               |
  | 下载、预览                               | 当前登录用户本人           |

  ## 3. 目录与命名（摘要）

  完整规则见《设计资产目录与命名规范（草案 v0.2）》。

  ```
  /设计资产/
  ├── 01已中标项目/
  │   └── 01酒业/                                行业（系统按对照表建）
  │       └── 07泸州老窖/                         企业（系统按对照表建）
  │           └── P2026-0012_泸州老窖_中秋礼盒/    项目（业务人员建）
  │               ├── 01定稿文件/
  │               ├── 02设计方案/
  │               ├── 03拍摄照片及视频/
  │               ├── 04授权文件/
  │               ├── 05 详情页/
  │               ├── 套装/         全家福主图（打标）
  │               ├── 单品/         所有单品主图（打标），含从套装拆出的和独立的
  │               ├── 套装档案/     系统生成
  │               ├── 单品档案/     系统生成
  │               ├── _历史版本/    系统生成
  │               └── _项目档案.txt  系统生成
  ├── 02未中标项目/                  结构同上
  └── _已作废项目/                   整项目作废后移到这里
  ```

  - 项目文件夹名：`立项编号_企业名_项目名`。
  - 立项编号：**沿用公司立项时的唯一编号**。历史项目没有编号的，由系统发放 `H` 前缀编号（如 `H2025-0001`）。格式校验规则待公司编号样例确定后补充。
  - 五个资料夹名称按业务现状**原样使用**，含 `05 详情页` 中的空格。业务要求缺资料时也保留空文件夹。
  - **资料夹内部放什么、怎么命名，工作台不检查、不干涉。**
  - `套装/` 只放全家福，`单品/` 平铺放全部单品主图。文件名由产品部门命名，对系统只是展示名，不承担任何结构含义。
  - 业务人员上传的包里不得出现系统生成的四项。

  ## 4. 数据对象、编号与状态

  ### 4.1 对象

  卡片柜是工作台电脑上的本地数据库。

  | 对象            | 关键内容                                                     |
  | --------------- | ------------------------------------------------------------ |
  | 项目            | 立项编号、企业、行业、是否中标、项目名、当前路径、状态、编号来源（公司编号 / 系统补发） |
  | 批次            | 批次号、所属项目、类型、责任人、状态、临时区路径、审核轮次、初审人、终审人 |
  | 文件            | 相对路径、大小、修改时间、指纹、是否有效                     |
  | 商品            | 商品编号、类型（套装 / 单品）、展示名、主图文件、状态、档案路径 |
  | 套装-单品关系   | 套装商品编号、单品商品编号、来源（AI 推荐 / 人工）。多对多   |
  | 标签值          | 商品、字段、值、来源（AI / 人工）、AI 原值                   |
  | 历史版本        | 旧指纹、原位置、现位置、发生批次、日期                       |
  | 永久链接        | 指向商品、文件或项目                                         |
  | 标签字段        | 字段名、填写说明、顺序、是否启用。没有可选值                 |
  | 企业→行业对照表 | 企业标准名、别名、行业、序号。只由管理员按线下结论录入       |
  | 角色表          | NAS 账号、角色                                               |
  | 日志            | 只追加                                                       |

  批次类型：首次入库、补充、改名、修改标签、作废、移动、物理删除、档案修复。

  ### 4.2 商品编号

  - 格式：`立项编号-三位流水`，如 `P2026-0012-001`。
  - 终审通过、执行入库时发放。套装和单品共用一套流水。
  - 发放顺序：单品（按文件名排序）→ 套装。
  - 一经发放不变：改展示名、替换主图、移动项目、改套装关系都不换号。
  - 补充包新增的商品接着原项目往后排。

  ### 4.3 套装与单品的关系

  文件夹不表达从属关系，关系由系统建立、由人确认：

  1. 第一遍 AI 打完全部单品，得到每个单品的名称和标签。
  2. 第二遍解析每张全家福时，把该项目**全部单品的名称和标签**一起交给模型，让它判断全家福里出现了哪些单品，输出推荐清单。
  3. 核对页上每张套装图有「包含的单品」区域，AI 推荐的已勾选，上传人可取消、可补勾。**每张套装图的关系必须经人确认，否则不能提交。**
  4. 一个单品可以属于多个套装。
  5. 全家福里有而 `单品/` 里没有单独主图的商品，不能被单独搜索，系统不处理。
  6. 入库后修改关系走「修改标签」审批线。

  ### 4.4 指纹

  - 按文件内容计算的哈希值，上传时边接收边计算。
  - 200MB 及以下算完整指纹；更大的算快速指纹（开头、结尾各几 MB 加大小），有歧义时补算完整指纹。
  - 记录在卡片柜、项目档案、SKU 档案三处。

  ### 4.5 永久链接

  | 链接     | 指向         | 说明                             |
  | -------- | ------------ | -------------------------------- |
  | 商品链接 | 商品编号     | 永远指向该商品当前有效的主图     |
  | 文件链接 | 某个具体文件 | 包括历史版本                     |
  | 项目链接 | 立项编号     | 打开项目页，按五个资料夹列出文件 |

  搜索结果给商品链接和项目链接。**从主图到设计文件的映射是项目级的**：搜到商品 → 所属项目 → 项目下各资料夹。商品与具体源文件的一一对应需要人工标注，第一版不做，作为后续可选功能。

  链接打开时验证登录身份，用登录人的 NAS 读权限取文件，并记日志。

  ### 4.6 批次状态

  ```
  上传中 ──中断──→ 上传中断 ──继续上传──→ 上传中
     ↓ 全部传完
  已暂存（等上传人确认）
     ↓ 上传人点「确认，开始 AI 处理」
  AI 处理中 ──全部失败──→ AI 处理失败 ──重试──→ AI 处理中
     ↓ 完成（允许部分图片失败）
  待核对
     ↓ 上传人提交
  待初审 ──驳回──→ 已驳回 ──修改后重新提交──→ 待初审（轮次 +1）
     ↓ 初审通过
  待终审 ──驳回──→ 已驳回 ──修改后重新提交──→ 待初审（轮次 +1）
     ↓ 终审通过
  入库中 ──中断──→ 入库异常 ──终审点「继续」──→ 入库中
     ↓
  已入库
  
  任何未通过终审的状态 ──撤回──→ 已撤回
  ```

  **任一级驳回都退回上传人，重新提交后从初审重新开始。**

  | 状态                       | 等谁                             |
  | -------------------------- | -------------------------------- |
  | 上传中 / 上传中断 / 已暂存 | 上传人                           |
  | AI 处理中                  | 系统                             |
  | AI 处理失败                | 上传人或管理员重试               |
  | 待核对 / 已驳回            | 批次责任人                       |
  | 待初审                     | 任一初审                         |
  | 待终审                     | 任一终审（不能是本批次的初审人） |
  | 入库中                     | 系统（终审身份）                 |
  | 入库异常                   | 终审                             |
  | 已入库 / 已撤回            | —                                |

  ### 4.7 商品状态

  有效 → 已作废 → 已删除。有替换批次在审核中时，搜索仍显示旧版本。

  ## 5. 全流程总览

  ```
  业务人员在本机整理好项目文件夹（历史项目同样方式）
          ↓
  ① 登录                     NAS 账号密码
          ↓
  ② 首页 → 上传新项目         勾选是否中标 → 拖入文件夹
          ↓
  ③ 浏览器端预检              只拦真正会导致系统无法处理的问题
          ↓
  ④ 上传到 NAS 临时区         分片、断点续传；传完由上传人确认
          ↓
  ⑤ AI 处理                  查对照表得位置；打单品 → 打套装并推荐包含关系
          ↓
  ⑥ 上传人核对并提交          所有字段可改；处理黄色项；确认套装包含关系
          ↓
  ⑦ 初审                     整包通过 / 整包驳回
          ↓
  ⑧ 终审                     相同内容再审；可改位置；整包通过 / 整包驳回
          ↓ 通过
  ⑨ 入库执行                  终审身份：移动 → 发商品编号 → 写档案 → 登记 → 生成链接
          ↓
  ⑩ 已入库                    可搜索、可下载
  ```

  ## 6. 首页与发起上传

  ### 6.1 首页

  **上传人**：

  1. 待办条：「2 个批次等你核对」「1 个批次被驳回」。
  2. 我的批次：批次号、项目、类型、状态、最后更新时间。
  3. 入口：「上传新项目」「对已入库项目操作」。

  **初审**多「待初审」页。**终审**多「待终审」页，以及「入库未完成」「待修复档案」提示。**管理员**多：巡检报告、日志、角色表、标签字段、对照表、临时区占用。

  ### 6.2 发起上传

  1. 点「上传新项目」，勾选「已中标 / 未中标」。
  2. 拖入项目文件夹（或点「选择文件夹」）。
  3. 系统从文件夹名第一段读出立项编号：
     - 编号已在库中 → 转补充流程（13.2）；
     - 编号不在库中 → 进入预检。
  4. 历史项目没有公司编号的，上传人在文件夹名第一段填 `H`，系统在上传确认页为其发放 `H2025-0001` 这样的编号，并提示上传人把本机文件夹改名后重新拖入（或由系统在临时区落盘时直接使用新名）。

  ### 6.3 历史项目

  与新项目完全相同：业务人员把旧项目拉到本机、整理成规范结构、走浏览器上传。旧库在迁移期间不删减，迁移完成后由业务部门决定去留。公共素材第一阶段不纳入。

  ### 6.4 限制

  - 一次只能上传一个项目文件夹，拖入多个即拦截。
  - 同一个人同时只进行一个上传，第二个排队。

  ## 7. 选择文件夹与预检

  ### 7.1 交互

  ```
  拖入文件夹 / 选择文件夹
     ↓ 浏览器只读取清单：相对路径、大小、修改时间，不上传内容
  预检结果页
     ├── 左：文件夹树，红（拦截）/ 黄（提醒）/ 灰（忽略）
     ├── 右：问题清单，写明哪个文件、什么问题
     └── 底：「有 N 个拦截项，请修改后重新拖入」或「开始上传」
     ↓ 无拦截项，每类提醒都勾了「我已知晓」
  确认框：P2026-0012 · 泸州老窖 · 已中标
          目标 01已中标项目 / 01酒业 / 07泸州老窖 /（企业不在对照表时显示「位置待定」）
          86 个文件 · 3.2 GB · 预计 12 分钟
     ↓ 确认
  开始上传
  ```

  - 所有浏览器支持拖入，并提供「选择文件夹」按钮兜底。不做 zip 上传。
  - 预检在浏览器端完成，只有「编号是否已存在」询问服务器。
  - 在本机改完后需重新拖入整个文件夹。
  - 「已知晓」勾选记入批次，两级审核都能看到。

  ### 7.2 预检规则

  原则：**只拦截会让系统无法处理的问题**；业务整理得是否规范，交给人审。

  | #    | 检查项                                                       | 处理                                     |
  | ---- | ------------------------------------------------------------ | ---------------------------------------- |
  | 1    | 项目文件夹名不是 `编号_企业_项目名` 三段，或编号段为空       | 拦截                                     |
  | 2    | 立项编号已在库中                                             | 转补充流程                               |
  | 3    | 任意层级含文件系统非法字符 `\ / : * ? " < > |`               | 拦截                                     |
  | 4    | 路径总长超过 200 字符                                        | 拦截                                     |
  | 5    | 出现系统保留的文件夹或文件（`套装档案` `单品档案` `_历史版本` `_项目档案.txt`） | 拦截                                     |
  | 6    | `套装/` 或 `单品/` 里有非图片文件或子文件夹                  | 拦截                                     |
  | 7    | `套装/` 和 `单品/` 都为空                                    | 提醒                                     |
  | 8    | 01～05 任一资料夹缺失                                        | 提醒                                     |
  | 9    | 项目名含中点、全角标点、空格等不建议字符                     | 提醒                                     |
  | 10   | 根目录散文件、规定之外的文件夹                               | 不检查                                   |
  | 11   | 主图分辨率、文件名写法、同名                                 | 不检查（等产品部门命名规则确定后再评估） |
  | 12   | `Thumbs.db` `.DS_Store` `desktop.ini` `~$` 临时文件          | 忽略，不上传                             |

  ## 8. 上传

  ### 8.1 过程

  1. 服务端创建批次，记录文件清单。
  2. 浏览器把文件切成 8MB 分片，3 个文件并行（可配置）。
  3. 服务端用上传人的 NAS 身份把分片写到 `临时区/批次号/相对路径`，不在工作台电脑落第二份。
  4. 顺序：主图 → 小文件 → 大源文件。
  5. 每个文件传完：核对大小，得到指纹。
  6. 主图传完时生成三张小图存在工作台电脑本地缓存：300px 缩略图、1600px 预览图、长边 1024px 且去掉拍摄信息的送审图。本地缓存不写回 NAS。

  ### 8.2 页面

  总进度条、当前文件、已完成数 / 总数、预计剩余时间；每个文件一行。

  ### 8.3 中断与续传

  批次变为「上传中断」，已传的保留。首页点「继续上传」→ 重新拖入同一文件夹 → 按相对路径、大小、修改时间比对：已传完跳过，半途的续传，有变化的重传，清单不一致时列出差异让上传人确认。

  ### 8.4 会话超时

  上传持有自己的令牌，会话过期不中断上传。

  ### 8.5 取消

  上传中可取消：删除临时区该批次文件，标记「已撤回」，日志留痕。

  ### 8.6 传完后的确认

  批次进入「已暂存」，显示「N 个文件已到达临时区，指纹已计算」。**上传人点「确认，开始 AI 处理」才进入下一步。**

  ### 8.7 临时区清理

  不自动清理。管理员在「临时区占用」里人工决定。

  ## 9. AI 处理

  ### 9.1 顺序

  1. 存放位置

     ：从文件夹名第二段取企业名，查对照表。

     - 查到 → 得到行业，输出推荐路径。
     - 查不到 → 位置标为「待定」。不调用模型猜行业，不提醒上传人，不阻塞流程。由终审在通过前从现有目录树选择；目录树里没有这家企业，终审暂不通过，等管理员按线下结论录入对照表后再处理。

  2. **第一遍：单品**。逐张打标。

  3. **第二遍：套装**。逐张打标，同时输入该项目全部单品的名称和标签，让模型推荐「包含的单品」。

  4. 完成后批次变为「待核对」，责任人待办 +1。

  ### 9.2 打标规则

  - 平台：阿里云百炼。具体模型在技术细节阶段确定。
  - 只发送主图的送审图。资料夹里的任何文件都不发送。
  - 标签字段与填写规则见 9.5（业务已确认）。模型按每个字段的填写说明自由填写。
  - 模型另生成一段自由描述供搜索兜底。
  - 并行 3 路（可配置）。每张图失败自动重试 3 次。

  ### 9.3 自动标黄

  | 情况                     | 标在哪     |
  | ------------------------ | ---------- |
  | 模型填了「无法判断」     | 该字段     |
  | 单品主图里识别出多个商品 | 该图       |
  | 套装推荐的单品清单为空   | 套装那张图 |

  ### 9.4 失败处理

  | 情况                         | 处理                                                         |
  | ---------------------------- | ------------------------------------------------------------ |
  | 部分图片重试 3 次仍失败      | 不阻塞。批次照常进核对，失败的图标红，核对页单张重试或手工填写 |
  | 全部失败                     | 停在「AI 处理失败」；上传人和管理员都可「重试整批」；管理员收异常 |
  | 超过 30 分钟无进展（可配置） | 提醒管理员                                                   |

  AI 处理中可撤回批次。

  ### 9.5 标签字段

  | 字段     | 填什么（给模型和人的填写说明）         | 示例                               |
  | -------- | -------------------------------------- | ---------------------------------- |
  | 品类     | 这是什么东西                           | 保温杯、雨伞、茶具套装             |
  | 材质     | 主要材料                               | 陶瓷、304 不锈钢、胡桃木           |
  | 主色     | 主要颜色                               | 中国红、哑光黑                     |
  | 风格     | 设计风格                               | 国潮、极简、复古                   |
  | 节日场景 | 适用的具体节日；不针对节日就写「通用」 | 春节、中秋、圣诞、万圣节           |
  | 受众群体 | 给谁用、送给谁                         | 企业客户、员工、长辈、儿童         |
  | 使用场景 | 用途和使用的场合                       | 商务社交、日常居家、户外出行       |
  | 尺寸     | 大小的描述                             | 掌心大小、约 20cm 高、桌面摆件尺寸 |
  | 工艺     | 制作或装饰工艺                         | 烫金、激光雕刻、釉下彩             |
  | 物料名称 | 物料的称呼                             | 双层玻璃杯、伸缩折叠伞             |
  | 结构     | 组成部分和形态结构                     | 杯身加杯盖、三折伞骨、抽屉式礼盒   |

  规则：

  - **全部字段由大模型预填，人工可以任意修改。** 没有固定的可选值，填写内容是自由文本。
  - **不限数量**：一个字段可以写多个值，用顿号「、」分隔。
  - 模型看不出来的写「无法判断」，不编造。
  - 没有人工必填字段。
  - 同一个意思的不同说法（「过年」与「春节」、「领导」与「企业客户」）不在入库时统一，交给检索时的大模型理解。
  - 字段清单由管理员在「字段管理」里维护：可以增删字段、改名、调整顺序、修改填写说明；不维护可选值。

  ## 10. 上传人核对与提交

  ### 10.1 谁能核对

  批次责任人（默认上传人）和管理员。换人由管理员改责任人。

  ### 10.2 页面

  ```
  ┌ 顶部 ──────────────────────────────────────────────────────────┐
  │ P2026-0012 泸州老窖 中秋礼盒 · 位置 01已中标/01酒业/07泸州老窖     │
  │ 待处理：黄色 5 项 · 套装关系未确认 1 个 · 打标失败 1 张  [提交审核] │
  ├ 左：主图列表 ───┬ 中：大图 ────────┬ 右：标签表单 ───────────────────┤
  │ ▾ 套装          │ 当前选中的主图     │ 品类  [摆件 ▾]       AI       │
  │   中秋礼盒A  黄 │ 可缩放            │ 材质  [陶瓷][木]     已改      │
  │   中秋礼盒B     │ 选中套装时可并排   │ 自由描述（AI 生成，可改）       │
  │ ▾ 单品          │ 显示它包含的单品   │ ───── 套装图才有 ─────        │
  │   酒瓶          │                  │ 包含的单品（AI 推荐，请确认）   │
  │   月饼盒     红 │                  │ ☑ 酒瓶 ☑ 月饼盒 ☑ 手提袋       │
  │   定制酒杯      │                  │ ☐ 酒瓶-小 ☐ 定制酒杯           │
  │ [批量修改][追加] │                  │ [确认关系]                    │
  └────────────────┴──────────────────┴──────────────────────────────┘
  底部：资料夹文件清单（折叠，只列名称和大小）
  ```

  ### 10.3 规则

  - **所有字段都可编辑，可改可不改，不强制逐条点确认。** 业务管理上要求"人工审核每一条"，由他们自行执行，系统只提供能力。
  - 每个字段是自由文本输入框，可以写多个值（顿号分隔），不限数量。输入时提示库里已经用过的说法供参考，可以不选。
  - 每个字段显示来源，人工改过的悬停可见「AI 原值 → 人工值」。
  - **AI 自动标黄的项必须处理**：改掉，或点「确认 AI 值正确」。
  - 红色的图：单张重试，或手工填写。
  - **每张套装图的「包含的单品」必须点「确认关系」。**
  - 自由描述可修改。
  - 批量修改：多选图片，统一设置若干字段。
  - 自动保存草稿。
  - 上传人不能修改存放位置，有异议写在备注里。
  - 提交前可填「给审核的备注」。
  - 「提交审核」在黄色清零、红色处理完、套装关系全部确认后可点击。

  ### 10.4 追加与移除主图

  - **追加**：在核对页单独上传图片到批次的 `套装/` 或 `单品/`。新追加的图单独跑 AI；追加单品后，已确认的套装关系不自动改变，但相关套装会重新标黄提示复核。
  - **移除**：移到批次回收区，不入库。移除的单品自动从所有套装关系里去掉。

  资料夹内的文件在核对阶段不能增减。

  ## 11. 初审与终审

  ### 11.1 两级的共同点

  - 审核内容**完全相同**，目的是两个人把关。
  - 队列按提交时间排列，显示项目、上传人、商品数、文件量、等待时长、轮次。
  - 审核页布局同核对页，标签**只读**。右侧审核信息：

  ```
  存放位置   01已中标项目 / 01酒业 / 07泸州老窖        [修改]（终审可改；初审只能看）
             或：位置待定——企业「XX」不在对照表中
  预检提醒   缺少 04授权文件 · 上传人已知晓
  核对记录   人工修改 6 处 · 确认 AI 值 3 处 · 手工补标 1 张 · 追加 1 张
  套装关系   中秋礼盒A → 酒瓶、月饼盒、手提袋（AI 推荐 3，人工补 0）
  上传人备注 "……"
  资料夹     01定稿文件 12 个 · 02设计方案 5 个 · 03拍摄 0 个 · 04授权 0 个 · 05 详情页 3 个
  审核清单   □ 存放位置正确   □ 项目命名与编号无误   □ 一图一品
             □ 套装与单品关系正确   □ 标签合理   □ 无不当内容
  
  [通过]   [驳回]
  ```

  - **审核清单必须全部勾选才能通过。**
  - 可在图片上钉意见，随驳回一起发出；通过则作废。
  - **驳回必须填总体意见，整包驳回，退回上传人。** 上传人修改后重新提交，从初审重新开始，轮次 +1。审核页可见历次意见。
  - 待审核超过 3 个工作日（可配置），提醒管理员。
  - 不能部分通过。

  ### 11.2 初审

  - 任一初审角色的人可领取。
  - 不能修改存放位置（看到"位置待定"也照常审核标签和结构）。
  - 通过 → 批次进入「待终审」。

  ### 11.3 终审

  - 任一终审角色的人可领取，**但不能是本批次的初审人**。
  - 可以修改存放位置：中标状态、行业、企业都可改，只能在现有目录树里选。记录「原位置 → 新位置」。
  - 位置待定且目录树里没有该企业：不能通过，页面提示"等待管理员录入对照表"。管理员录入后终审再处理。
  - 通过 → 立即以终审身份执行入库（第 12 节）。

  ## 12. 入库执行

  以**终审本人的 NAS 身份**顺序执行，每步记一次，失败从未完成的那步继续。

  | 步   | 动作                                                         |
  | ---- | ------------------------------------------------------------ |
  | 1    | 确认目标位置不存在同名或同编号的项目文件夹                   |
  | 2    | 行业、企业文件夹不存在则按对照表新建                         |
  | 3    | 把项目文件夹从临时区移动到目标位置（回收区的主图不随之移动） |
  | 4    | 发放商品编号：先单品后套装                                   |
  | 5    | 写 `单品档案/`、`套装档案/`，套装档案写入包含单品的编号，单品档案写入所属套装的编号 |
  | 6    | 新建 `_历史版本/`，写 `_项目档案.txt`                        |
  | 7    | 登记卡片柜：项目、文件、指纹、商品、关系、标签               |
  | 8    | 生成永久链接                                                 |
  | 9    | 批次「已入库」，通知上传人、初审、终审                       |

  **部署要求**：临时区与正式目录在 NAS 同一存储卷，移动才是瞬时的。

  **中断**：批次变「入库异常」，记下停在第几步。终审下次登录后首页提示，点「继续」接着跑。管理员只收通知。

  ## 13. 入库后的操作

  ### 13.1 总则

  - 入口：「对已入库项目操作」→ 找到项目 → 项目页。
  - **每一种操作都走：发起 → 初审 → 终审 → 终审通过时以终审身份落盘并更新档案、卡片柜。** 任一级驳回退回发起人。
  - 同一项目同时只允许一个未完成的操作批次。
  - **【待定】** 改名、修改标签这类不动文件内容的轻操作是否也需要两级，还是一级即可。

  **项目页**

  ```
  P2026-0012_泸州老窖_中秋礼盒   位置 01已中标/01酒业/07泸州老窖   入库 2026-11-10
  [补充] [改名] [修改标签] [作废]       终审另有 [移动] [整项目作废] [物理删除]
  
  商品 8 个    缩略图、编号、展示名、状态；套装可展开看包含的单品
  资料夹       01定稿文件 / 02设计方案 / 03拍摄照片及视频 / 04授权文件 / 05 详情页，各自列文件
  历史版本     可下载、可对比
  操作记录     本项目全部日志
  ```

  ### 13.2 补充（含替换）

  1. 上传人在本机准备补充包：同一立项编号，只放新增或要替换的文件，按原文件夹结构摆放。
  2. 系统发现编号已在库中，转入补充流程。只认编号，项目名不一致标黄提醒。
  3. 按相对路径逐个判定：新增 / 重复（跳过）/ 冲突（标红，上传人选「替换」或「另存为新文件」，另存自动命名 `原名_v2`）。
  4. AI 只处理新主图。被替换的主图重新打标，沿用原商品编号。新增单品后，相关套装标黄提示复核关系。
  5. 核对、初审、终审。审核页并排对比新旧文件，汇总新增 / 替换 / 跳过数。
  6. 终审通过：旧文件移入 `_历史版本/`（文件名加日期），新文件合并，新商品发编号，更新档案、卡片柜。商品链接自动指向新主图。

  补充包只表达新增和替换。

  ### 13.3 改名

  | 改什么     | 落盘                                   |
  | ---------- | -------------------------------------- |
  | 项目名     | 重命名项目文件夹（编号段、企业段不变） |
  | 商品展示名 | 重命名主图文件和它的档案文件           |

  校验新名不含非法字符、项目内不重名。通过后联动更新 SKU 档案、相关套装档案、项目档案、卡片柜。编号、链接不变。

  ### 13.4 修改标签与套装关系

  在核对页同样的界面修改已入库商品的标签、自由描述或套装包含关系，不动图片。记录旧值新值。通过后更新卡片柜和 SKU 档案。

  ### 13.5 作废

  - 勾选商品或资料文件，填原因。
  - 作废套装只作废那张全家福，关系表里的记录随之失效，单品不受影响；可勾选「连同包含的单品一起作废」。
  - 通过后：文件移入 `_历史版本/`，商品状态「已作废」，搜索不显示，链接提示「已作废」。
  - **整项目作废**：终审发起，整个文件夹移到 `/设计资产/_已作废项目/`。
  - 作废可恢复（终审发起）。

  ### 13.6 移动

  终审发起，纠正中标状态、行业或企业，只能移到现有目录树中的位置。填原因后执行。链接不变。

  ### 13.7 物理删除

  | 项     | 规则                                                         |
  | ------ | ------------------------------------------------------------ |
  | 谁     | 只有终审，自己发起、自己执行                                 |
  | 范围   | 只能删**已作废**内容：单个历史版本文件、已作废商品、已作废整项目 |
  | 冷静期 | 作废满 30 天（可配置）；提前需填例外原因                     |
  | 确认   | 列出全部待删文件；手动输入立项编号或商品编号                 |
  | 留痕   | 卡片柜状态「已删除」，保留原路径、指纹、标签、作废与删除的时间和原因；日志一条；链接提示删除日期和原因 |
  | 巡检   | 删除前登记「预期消失」                                       |

  此规则为 IT 内部规则，不对业务部门另行宣讲。

  ### 13.8 撤回

  任何未通过终审的批次都可由责任人撤回。

  ## 14. 档案与巡检

  ### 14.1 三层信息卡

  对应业务确认的「项目、单品、套装各自的信息卡」：

  | 档案     | 位置                   | 一份对应 |
  | -------- | ---------------------- | -------- |
  | 单品档案 | `单品档案/展示名.json` | 一个单品 |
  | 套装档案 | `套装档案/展示名.json` | 一个套装 |
  | 项目档案 | `_项目档案.txt`        | 一个项目 |

  - 只由系统写入。与卡片柜不一致时以卡片柜为准。
  - 每次终审通过的操作立即更新。

  **套装档案示例**

  ```json
  {
    "格式版本": 2,
    "商品编号": "P2026-0012-007",
    "商品类型": "套装",
    "展示名": "中秋礼盒A",
    "立项编号": "P2026-0012",
    "主图相对路径": "套装/中秋礼盒A.jpg",
    "主图指纹": "a02b…",
    "包含单品": [
      {"商品编号": "P2026-0012-002", "来源": "AI推荐"},
      {"商品编号": "P2026-0012-003", "来源": "AI推荐"},
      {"商品编号": "P2026-0012-004", "来源": "人工补充"}
    ],
    "标签": {},
    "标签来源": {},
    "自由描述": "……",
    "识图模型": "……",
    "入库时间": "2026-11-12",
    "状态": "有效",
    "结束标记": "完"
  }
  ```

  单品档案用「所属套装」列出所有包含它的套装编号（可多个）。没有「结束标记」的档案视为损坏。

  **项目档案示例**

  ### 14.2 巡检

  - 每天凌晨一次，**只读不写 NAS**，用只读巡检账号。
  - 只列目录，发现变化才算指纹。

  | 情况                             | 处理                             |
  | -------------------------------- | -------------------------------- |
  | 整个项目文件夹被移动             | 按编号认出，更新卡片柜路径       |
  | 单个文件位置变、内容没变         | 指纹确认后更新路径               |
  | 同一位置内容变了                 | 报告「未经工作台的修改」         |
  | 卡片柜里没有的文件               | 报告「未经工作台的新增」，不收录 |
  | 文件找不到且不在「预期消失」名单 | 报告「丢失」                     |
  | 档案缺失、损坏、不一致           | 列入「待修复档案」               |

  - 档案修复由终审登录后一键执行。
  - 报告发给管理员。
  - 链接找不到文件时按「记录路径 → 编号定位项目 → 文件名 + 大小 + 修改时间 → 完整指纹」四层查找。
