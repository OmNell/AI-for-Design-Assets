# NAS 设计资产工作台 · Windows 内网部署和运维

当前交付为 V1.0 候选。先按本文完成现场验收，再由公司负责人批准上线。构建、软件包验证和隔离数据演练的实测结果见 [V1 验收报告](../docs/V1-验收报告.md)。

## 部署前准备

- 一台公司管理的 64 位 Windows 主机，支持本机 ACL 的 SSD 数据盘，系统范围安装 Python 3.12。目标主机仅需 Python 和配置的依赖下载来源。公司断网时由 IT 在系统安装前准备批准的 Python 软件包镜像，并配置 pip 访问。
- 一份候选 ZIP 和通过独立可信渠道取得的 SHA-256。NSSM 从公司批准的软件源或 NSSM 官方发行渠道取得，使用经 IT 核准的 Windows x64 二进制。记录二进制的 SHA-256 及文件属性的 `ProductVersion`，安装脚本同时检查两项。安装命令从已验证的解压目录运行。
- 配置固定内网 DNS，例如 `nas-workbench.company.local` 指向 Windows 主机内网 IP。设置中的 `public_base_url` 必须使用实际域名和 `http://域名:8080`。服务主机换 IP 时改 DNS，原项目、商品和文件链接继续使用原域名及短 ID。
- 准备公司批准的私有 IPv4 网段清单、独立的初始管理员 NAS 账号、系统账号和至少三名互相独立的测试账号。服务主机须能访问 NAS 的 TCP 445，NAS 须启用 SMB2/3 并支持签名。百炼使用 HTTPS。

**HTTP 风险确认**
工作台采用 HTTP。NAS 登录口令和工作台 Cookie 在局域网链路上可能被明文监听或劫持。IT 应隔离工作台网络，按客户端来源和网段限制 TCP 8080，检查现有防火墙策略、代理和公网映射，在授权与拒绝网段分别验证。禁止公网和访客网接入。安装时以 `-AcceptHttpRisk` 记录已作风险确认。工作台到 NAS 使用要求签名的 SMB 会话，百炼连接继续使用 HTTPS。

## 群晖目录和权限

| 身份 | `/设计资产/` | `/工作台临时区/` | `/_工作台备份/` |
|---|---|---|---|
| 普通员工、初审 | 授权范围内只读 | 本人上传批次读写 | 无权限 |
| 终审 | 审批通过后按本人 NAS 权限写入 | 按授权范围读写 | 无权限 |
| 管理员个人账号 | 按个人 NAS ACL，管理角色本身不授予正式写权限 | 按 ACL 读取和清理终态批次 | 常规 SMB 无权限，工作台管理员可下载验证通过的归档 |
| `wb-system` | 只读巡检和灾难恢复 | 无权限 | 读写，保留历史备份 |

让 NAS 管理员检查组成员、继承和实际有效权限。恢复 ZIP 含密钥，应限制备份区读取范围。缩略图与数据盘预留按实际图片数量、备份规模及 WP12 物理历史版本估算。

## 安装

1. 将 ZIP 和校验值交给 IT。先用 `Get-FileHash -Algorithm SHA256` 比对批准值，再解压到受控暂存目录。
2. 在提升权限的 Windows PowerShell 中进入解压目录，执行：

   ```powershell
   .\deploy\install.ps1 -Package 'D:\Staging\nas-workbench-v1.1.5-rc.1-windows.zip' -PackageSha256 '<批准的 SHA-256>' -Nssm 'D:\Staging\nssm.exe' -NssmSha256 '<批准的 NSSM SHA-256>' -NssmVersion '<文件属性 ProductVersion>' -AllowedCidrs @('10.42.10.0/24') -AcceptHttpRisk
   ```

   网段仅为命令示例。需要自选目录时传 `-Root 'D:\NASDesignWorkbench'`。已有目录或服务应走升级/恢复流程。
3. 按提示输入域名、群晖地址、共享名、工作根目录、系统账号和密码。工作根目录输入共享内相对路径，三个业务区自动派生。回车可保留原有共享顶层三区布局。密码使用隐藏输入，配置写入加密值。安装器初始化 SQLite 和密钥。服务以 LocalService 运行，使用发布目录自己的虚拟环境和后端工作目录，端口 8080，单进程，开机自启，异常退出自动重启。
4. 检查 `logs/service.stdout.log` 和 `logs/service.stderr.log`。NSSM 在启动和运行期间按约 10 MiB 轮换这两类日志，应用日志按天轮换。浏览器从授权网段访问固定域名。确认看到首页并验证 `/api/health` 的生产模式和数据库状态。
5. Windows 防火墙只创建一个工作台入站规则，适用 Domain 和 Private 配置文件，仅向填入的公司网段开放 TCP 8080。检查 GPO、默认入站策略及其他既有规则是否额外放行。不要使用 Any。

## 首次登录和日常运营

- 初始管理员用 NAS 账号登录。在「管理 → 角色管理」分配上传、初审、终审、管理员角色。提交人、初审与终审必须是三位不同账号。截图点包括角色表及独立账号的阻断结果。
- 在企业行业对照表录入正式名称、序号和别名。固定 11 标签分别是品类、材质、主色、风格、节日场景、受众群体、使用场景、尺寸、工艺、物料名称、结构。管理员可维护填写说明和排序，字段身份固定。截图点包括对照表、固定字段和排序。
- 从「设置」填写百炼 API、识图、文本和向量模型，执行三项连接测试。升级向量模型使用候选索引全量核验和切换功能。截图点包括三个模型状态和候选覆盖率。
- 「管理 → 运营管理」查看中国标准时间 02:00 巡检和 03:00 备份。需要时手动补跑。若巡检报告档案损坏，由终审角色发起修复草稿并经两级审核。临时区只清理已核实的终态批次或孤儿文件，按个人 NAS 会话核对和确认。保留操作日志。

## 上线自检

从已安装候选版本运行 `scripts/preflight_check.py`。在安装目录读取 `installation.json` 的 `release` 找到发布目录，使用其中的 `.venv\Scripts\python.exe`。例如在该发布目录运行：

```powershell
.\.venv\Scripts\python.exe .\scripts\preflight_check.py --config 'C:\ProgramData\NASDesignWorkbench\configuration\config.yaml' --package '<候选 ZIP>' --package-sha '<批准的 SHA-256>' --report 'D:\Staging\preflight.json'
```

现场执行时加 `--network` 检查 DNS、HTTP、SMB TCP 445、系统账号 SMB 认证和共享访问，加 `--test-ai` 发送真实百炼最小请求。默认的本机校验不代表内网已通过。若要测同卷 rename，先由 NAS 管理员建立获批的 `_WP14验收` 开头的专用测试目录。加 `--write-probe` 及 `--employee`、`--final-reviewer`、`--temp-test-dir`、`--formal-test-dir`、`--backup-test-dir`，按提示输入测试身份密码。终审身份验证临时区移动到正式区。系统账号只可在授权备份测试目录写入，正式区禁止写入、临时区禁止访问的实际群晖权限由 IT 从有效 ACL 核对。NAS 容量、网络拒绝测试、设备隔离和既有永久链接须现场验收。

## NAS 存储设置

Windows 安装器配置 SMB 连接参数并指定初始管理员。公司内部署完成后，以管理员登录，在左侧系统导航打开「NAS 存储设置」。现有已绑定的三区直接显示在运行状态中。

1. 输入群晖私网 IPv4 或内网域名和一个普通 SMB 共享名。域名须通过内网 DNS 唯一解析为一个 RFC1918 IPv4。连接使用 TCP 445 和要求签名的 SMB 会话。
2. 输入当前管理员本人的 NAS 密码，测试 SMB 身份认证和共享访问。浏览授权目录，选择一个现有工作目录。也可输入共享内相对路径，例如 `部门/工作台`。NAS 管理员应提前建立其中的 `设计资产`、`工作台临时区`、`_工作台备份`，按上文权限表配置 ACL。浏览器中的目录选择只读取目录元数据。
3. 检查目录、影响和系统账号授权。普通员工和终审可分别使用经授权的实际测试账号检查。界面上的读写授权结果来自不写入数据的访问检查。实际继承 ACL、读写和清理效果请在已批准的隔离 NAS 目录现场验收。此前系统密码未变时可留空。换账号、地址或已固定的解析地址时重新输入系统账号密码。
4. 确认保存后，工作台显示「待重启」并暂停业务入口。维护窗口在提升权限的 PowerShell 执行 `Restart-Service -Name NASDesignWorkbench`，重新登录并打开「NAS 存储设置 → 刷新状态」。复检通过后才启用新会话池。复检失败会恢复原 YAML 并显示「应用失败」。查看 `logs/service.stderr.log` 和设置状态。
5. 已有资产、历史或批次记录时，根目录和共享变更必须走独立迁移。修改地址须验证原 NAS 的 SMB 身份及可用资产样本。上传、审核、入库、恢复、巡检或备份尚未结束时先结束工作，配置中心会列出冲突。

新版受管配置位于 `configuration/config.yaml`，其目录 ACL 仅允许管理员、系统和服务身份写入，安装根、应用程序及 NSSM 继续按原权限保护。旧版升级在停机和快照后将配置迁至受保护子目录，保留数据目录、密钥和旧配置备份。新版读取旧配置时忽略已退役的 DSM 字段，旧版回滚使用升级前的配置。安装根路径下原来的 `config.yaml` 是旧版布局。升级失败时回到原布局和原快照。

配置变更前的 YAML 副本位于本机 `data/nas-settings-previous.yaml`，由 `data/nas-settings-state.json` 记录校验值。外部编辑导致自动恢复无法确认时，由运维保持服务停止，核对副本与日志，再决定回退。恢复旧连接前须确认服务启用后没有在新根产生数据，或确认目标仍为同一套 NAS 资产和目录。旧的完整备份恢复流程也可获得运行时原配置。若按旧手工安装方式运行，配置文件所在目录须专用于工作台服务且可原子替换。

## 软件升级和回滚

1. 使用新的已验证解压目录运行 `deploy/upgrade.ps1 -Package <路径> -PackageSha256 <批准值>`。确认管理的安装状态和当前版本。
2. 在维护窗口通知业务暂停访问，确认没有额外放行 8080 的防火墙规则、GPO 或代理。脚本准备新虚拟环境，停止旧服务、核验进程退出并暂停托管防火墙规则，生成与恢复工具兼容的升级前快照，再迁移数据库和切换 NSSM 路径。回环检查成功后恢复原来的托管规则状态。旧版本保存在 `releases/`。核对 `logs/upgrades.log`、原数据和链接。
3. 健康检查失败会恢复旧应用、数据库、配置和密钥，失败升级数据另存在受限备份目录。核对是否有新业务写入，再决定手动回退。手动介入前停止工作台并确认进程退出，验证 `backups/pre-upgrade-*.zip`，由 IT 用原发布的 `deploy/ops.py rollback --root <安装目录> --package <快照> --service-stopped` 恢复，再通过 `common.ps1` 的服务切换函数加载旧版本。用 `icacls` 核验 LocalService 的密钥权限，并同步 `installation.json` 到旧版本。回滚必须使用与旧应用兼容的升级前数据库。
4. `0011–0020` 的老库迁移先在隔离副本执行。由开发环境或手工服务迁入时，先按照下节备份恢复步骤放入受管安装，核对配置、状态和 ACL，由 IT 决定切换窗口。

默认卸载只处理托管服务、应用和自己的防火墙规则。运行 `deploy/uninstall.ps1` 时会要求确认。保留数据、配置、密钥、日志、备份和 NAS 文件。若需要彻底清理本机数据，由 IT 另行确认及保留可恢复备份。

## 数据恢复

**场景 A：存在数据库备份包**
先从安装版本的目录运行下列命令。候选列表中的清单验证只检查 ZIP 结构和备份格式。选择最近的候选后，恢复工具会逐个核对文件 SHA-256、SQLite 完整性与外键、资产身份清单以及密文与密钥。候选损坏时可以重新选择较早的备份。

```powershell
.\.venv\Scripts\python.exe .\scripts\restore_backup.py --list-nas --config '<目标配置.yaml>'
.\.venv\Scripts\python.exe .\scripts\restore_backup.py --nas-backup '<列表中的备份名>' --config '<目标配置.yaml>' --target '<尚不存在的新目录>' --service-stopped --compare-nas
```

已有本地 ZIP 时用文件路径替换 `--nas-backup '<备份名>'`。工具在新目录中迁移数据库、废止原登录会话，并保存 `source-config.yaml`、可启动的 `config.yaml` 和 `restore-report.json`。目标配置提供新环境的监听地址、域名和 NAS 路径。隔离配置启用 `recovery.read_only`。用回环地址和独立端口启动验证实例，核对人员与角色、审核历史、原链接、两种搜索和预览下载。查看 `nas-difference.json`，在隔离恢复库补齐晚于备份的已发布档案，处理计划中的冲突。只能从保护的本机目录启动恢复实例。

**场景 B：SQLite 和全部备份丢失**
先以 `wb-system` 只读扫描，输出新报告，省略目标目录即只扫描：

```powershell
.\.venv\Scripts\python.exe .\scripts\rebuild_catalog.py --config '<config.yaml>' --report '<新的计划.json>'
```

有匹配的发布凭据、唯一最新版本和完整 SHA-256 才自动选中。新版在双审、档案、文件及正式向量通过后，先用本轮终审会话写入并读回恢复凭据，再提交 SQLite 的可见状态。SQLite 完好时，若提交中断，由本轮终审继续原批次；SQLite 和全部备份损毁时，可用已落盘凭据重建，再通过向量门禁。旧版本曾经发布但缺少凭据时，SQLite 尚存可在巡检后发起档案双审修复。SQLite 和备份均已损毁的旧档案仍需独立证据。人工选项 `--selection` 使用按项目编号索引的 JSON，各条含计划报告中的 `path`、`manifest_sha256` 与独立证明发布已完成的 `basis`。有两个冲突版本时请保留双方证据。凭据可信度依赖正式档案 ACL 和现场对未经工作台改动的审计。

加 `--target <尚不存在的隔离目录>` 重建原始项目、商品、文件、关系、标签、历史和链接。原始 NAS 正式区全程只读。显式加 `--rebuild-derived` 可生成缩略图并使用当前配置的模型走正式向量门禁。生产配置会调用真实百炼，使用前完成授权。派生失败的项目保持隐藏。处理后可用同样的来源与批准清单执行 `--resume-derived <原隔离目录>` 补跑。密钥也遗失时可加 `--prompt-system-password` 临时输入只读系统身份。数据库没有可证明的原会话、用户角色、审核记录、日志与调度历史时，报告列出缺失项。正式启用前由 IT 独立核准角色和启动配置。

### Windows 托管服务恢复切换

1. 在维护窗口停止原业务实例、隔离验证实例和目标 Windows 服务。加载目标版本的 `deploy/common.ps1`，使用 `Stop-Workbench <目标发布目录>` 核验目标服务、进程和端口已退出。记录现有防火墙规则状态，停用对客户端的工作台入站规则。
2. 在安装根的受保护 `backups` 下保留原 `data` 整个目录和原 `configuration/config.yaml`，包括 SQLite 的 WAL/SHM、密钥和 NAS 配置状态。原库可用时，还可先运行 `deploy/ops.py snapshot --root <安装根> --package <新的本机快照.zip> --service-stopped`。把隔离库的 `data` 复制到空的安装根 `data`，再把隔离配置复制到 `configuration/config.yaml`。设置 `paths.data_dir: ../data`，核对实际内网域名和端口 8080，保持 `recovery.read_only: true`。
3. 对安装根运行 `Protect-Directories`，用 `icacls` 核验数据、配置和密钥 ACL，并按安装流程为 LocalService 授权密钥。用当前发布的 `deploy/ops.py migrate --root <安装根>` 核验配置、密钥及数据库。启动服务后运行 `Test-Workbench <安装根> <目标发布目录>`，再用授权账号复核资产权限、链接和检索。确认同一套 NAS 正式资产只留一个写入实例后，才设置 `recovery.read_only: false`、重启并恢复原入站规则。
4. 开放业务写入前如验证失败，重新停机并把尝试切换的 `data` 和配置另存到受保护目录，再成对恢复原数据目录、原配置及原密钥。核验 LocalService ACL 和健康检查后按原规则恢复服务。已开放写入时，先停止写入并核对切换后的变更，再决定如何回滚。

## 常见问题及签署项

| 情况 | 检查位置 |
|---|---|
| 服务启动或停机失败 | NSSM 路径、应用错误日志、8080 监听进程及 LocalService 的数据目录 ACL |
| SMB 登录失败 | NAS TCP 445、SMB2/3、签名策略、账号状态和共享访问权限 |
| NAS 会话超时或上传慢 | 重新登录后按原设备流程恢复，检查固定分片大小、SMB ACL、共享路径和带宽 |
| 百炼失败 | 模型名、HTTPS、密钥状态、维度及并发。核对任务中心原因 |
| 旧链接打不开 | DNS 后缀、固定域名、源路径、角色与 NAS ACL，以及恢复报告中的冲突或隐藏状态 |
| 回滚失败 | 先停止服务，保留失败目录，核对升级前快照及其应用版本再恢复 |

签署人填写 Windows 安装、首次登录、开机自启、失败重启、升级回滚、卸载留存、授权网段及拒绝网段、实际 SMB ACL、同卷移动、百炼模型和维度、两类恢复、真实性能与 HTTP 风险确认。每项记录时间、环境、账号角色、证据和阻断项。完成后由公司批准是否创建正式版本标签。
